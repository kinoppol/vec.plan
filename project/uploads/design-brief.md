# Design Brief — ระบบบริหารโครงการและงบประมาณ สถานศึกษาอาชีวศึกษา

> เอกสารนี้สำหรับ **Claude Design** ใช้ออกแบบหน้าจอ (UI/UX) ของระบบ
> คู่กับเอกสาร `build-spec.md` ซึ่งเป็นข้อกำหนดสำหรับ Claude Code สร้างระบบจริง
> ชื่อสถานะ ชื่อฟิลด์ และกฎทั้งหมดในเอกสารนี้ต้องตรงกับ `build-spec.md`

---

## 1. ระบบนี้คืออะไร

เว็บแอปภายในวิทยาลัยอาชีวศึกษา (สังกัด สอศ.) สำหรับ **งานยุทธศาสตร์ แผนงานและงบประมาณ** ใช้ตลอดวงจรปีงบประมาณ (1 ต.ค. – 30 ก.ย.):

1. งาน/แผนกวิชา **เสนอโครงการ** พร้อมเหตุจำเป็น ผลกระทบ และงบประมาณ
2. งานแผนฯ ใช้ **เครื่องมือจำลองงบ** จัดชุดโครงการที่เงินแต่ละกองรับไหว แล้วเสนอที่ประชุม
3. ที่ประชุมมีมติ → ล็อกเป็น **แผนตั้งต้น**
4. ก่อนลงมือ ผู้รับผิดชอบ **ขออนุญาตดำเนินโครงการ** (อนุมัติชั้นที่ 2)
5. **ติดตาม** การดำเนินงาน การเบิกจ่าย และรายงานผล
6. **ปรับแผน** ได้ (แยก / รวม / เปลี่ยน / เพิ่มวงเงิน) โดยระบบเตือนเมื่อใช้งบเพิ่ม
7. **บริหารกองเงิน**: ประมาณการ เทียบ รับจริง และสมุดบัญชีที่ตรวจย้อนกลับได้ทุกบาท

คำถามหลักที่ทุกหน้าจอต้องช่วยตอบ: **เงินแต่ละกองเหลือเท่าไร · โครงการไหนติดอยู่ที่ใคร · เงินก้อนนี้มาจากไหนไปไหน**

## 2. ผู้ใช้

| บทบาท | อุปกรณ์หลัก | สิ่งที่ทำบ่อย | ความถนัดดิจิทัล |
|---|---|---|---|
| ครูผู้เสนอ / ผู้รับผิดชอบโครงการ | มือถือ + คอมพิวเตอร์ | กรอกเสนอโครงการ ขออนุญาต ส่งรายงานผล | ปานกลาง ไม่อยากกรอกเยอะ |
| หัวหน้างาน / หัวหน้าแผนกวิชา | มือถือ | เห็นชอบ/ส่งกลับ ดูโครงการของหน่วยงาน | ปานกลาง |
| รองผู้อำนวยการฝ่าย | มือถือ | เห็นชอบ ดูภาพรวมฝ่าย | ปานกลาง |
| **เจ้าหน้าที่งานวางแผนและงบประมาณ** (ผู้ใช้หลัก) | คอมพิวเตอร์จอใหญ่ | ทุกอย่าง: ตรวจ จำลองงบ ปรับแผน ออกรายงาน ตั้งค่า | สูง ใช้ Excel คล่อง |
| รองผู้อำนวยการฝ่ายแผนงานฯ | คอมพิวเตอร์ / มือถือ | ให้ความเห็น ดูแดชบอร์ด | ปานกลาง |
| ผู้อำนวยการ | มือถือ / แท็บเล็ต | อนุมัติ ดูภาพรวม | ปานกลาง ต้องการข้อมูลสั้นชัด |
| งานการเงิน / งานบัญชี | คอมพิวเตอร์ | บันทึกรับเงิน บันทึกเบิกจ่าย กระทบยอด | สูง |
| งานพัสดุ | คอมพิวเตอร์ | บันทึกเลขที่ใบสั่งซื้อ/สัญญา | ปานกลาง |
| กรรมการวิทยาลัย | แท็บเล็ต / เอกสารพิมพ์ | อ่านเอกสารเสนอและแดชบอร์ดสรุป | หลากหลาย |

ผลต่อการออกแบบ:
- งานแผนฯ ใช้หน้าจอที่ **ข้อมูลหนาแน่น** ได้ (ตาราง ตัวกรอง แป้นพิมพ์ลัด) — desktop-first
- หน้าที่ครูและผู้บริหารใช้ (เสนอ อนุมัติ ขออนุญาต รายงานผล แดชบอร์ดสรุป) ต้อง **ใช้บนมือถือได้ดี** (กว้าง 360 px)
- ปุ่มอนุมัติต้องเห็นเงินที่เกี่ยวข้องก่อนกดเสมอ

## 3. หลักการออกแบบ

1. **เงินแต่ละกองมีสีประจำ ใช้ซ้ำทุกหน้า** (ดูข้อ 7) — ผู้ใช้จำกองเงินจากสีได้
2. **ตัวเลขเงินอ่านง่าย**: จัดชิดขวา ใช้ตัวเลขความกว้างเท่ากัน (tabular numbers) คั่นหลักพัน ทศนิยม 2 ตำแหน่งในตาราง; การ์ดสรุปย่อเป็น "12.4 ล้าน"
3. **แยก "ประมาณการ" กับ "จริง" ให้เห็นด้วยตา**: ประมาณการใช้เส้นประ/สีอ่อน, จริงใช้สีทึบ
4. **สถานะมีป้าย (badge) สีเดียวกันทั้งระบบ** และมีข้อความกำกับเสมอ ไม่ใช้สีอย่างเดียว
5. **ทุกยอดเงินคลิกเจาะลงได้** ไปยังรายการเคลื่อนไหวที่ประกอบเป็นยอดนั้น
6. **ภาษาไทยทั้งระบบ ปี พ.ศ.** วันที่แบบ "6 ต.ค. 2569", ไตรมาสแบบ "ไตรมาส 1 (ต.ค.–ธ.ค.)", ปีงบแบบ "ปีงบประมาณ 2570"
7. **ไม่ลบ แต่ย้อนรายการ**: UI ไม่มีปุ่ม "ลบ" ข้อมูลการเงิน มีแต่ "ยกเลิก/กลับรายการ" พร้อมช่องเหตุผล
8. **เตือนก่อนพลาด**: ยอดติดลบ ใช้งบเพิ่ม เงินไม่พอ แสดงทันทีขณะกรอก ไม่รอกดบันทึก

## 4. โครงสร้างการนำทาง

แถบเมนูด้านซ้าย (ยุบได้) + แถบบน (เลือกปีงบประมาณ, ค้นหา, การแจ้งเตือน, ผู้ใช้/บทบาท) เมนูที่เห็นขึ้นกับบทบาท

```
หน้าหลัก (แดชบอร์ดตามบทบาท)
งานของฉัน (กล่องงานรออนุมัติ / รอรายงาน)
โครงการ
  ├ โครงการทั้งหมด
  ├ เสนอโครงการใหม่
  └ คำขอปรับแผน
พิจารณางบประมาณ        (งานแผนฯ)
  ├ ชุดพิจารณา
  └ มติที่ประชุม
กองเงิน                 (งานแผนฯ, การเงิน)
  ├ ภาพรวมกองเงิน
  ├ ประมาณการรายรับ
  ├ บันทึกรับเงิน
  └ สมุดบัญชี
การเงิน/พัสดุ           (การเงิน, พัสดุ)
  ├ บันทึกผูกพัน
  └ บันทึกเบิกจ่าย
รายงาน
ตั้งค่า                  (งานแผนฯ)
```

## 5. หน้าจอที่ต้องออกแบบ

ลำดับความสำคัญ: **P1** ต้องมีในชุดแรก · **P2** ชุดถัดไป

### 5.1 แดชบอร์ดงานแผนฯ (P1, desktop)

- ตัวกรองบนสุด: ปีงบ · ฝ่าย · แผนกวิชา/งาน · แหล่งเงิน
- การ์ด 4 ใบ: วงเงินทั้งหมด · อนุมัติแล้ว · จ่ายจริง · คงเหลือ (แต่ละใบมี sub-text เทียบประมาณการ)
- **ฐานะเงินรายกอง**: แท่งแนวนอนต่อกองเงิน แบ่งช่วง จ่ายจริง / ผูกพัน / จัดสรรยังไม่ใช้ / คงเหลือ พร้อมขีดแสดงประมาณการรับ
- **การใช้จ่ายสะสมเทียบแผน**: กราฟเส้นสะสม ต.ค.–ก.ย. (แผน = เส้นประ, จริง = เส้นทึบ, เส้นตั้ง "วันนี้")
- **สถานะโครงการ**: แท่งแยกตามฝ่าย สีตามสัญญาณไฟ
- **ต้องทำวันนี้**: รายการคำขอรออนุมัติ, รายงานค้าง, คำขอ "ใช้งบเพิ่ม", เงินรับจริงต่ำกว่าประมาณการ
- งบตามยุทธศาสตร์/มาตรฐานการอาชีวศึกษา: แท่งแนวนอน

### 5.2 แดชบอร์ดผู้บริหาร (P1, mobile-first)

การ์ดสรุป 4 ใบ · ฐานะเงินรายกอง · จำนวนโครงการตามสัญญาณไฟ · ปุ่ม "รออนุมัติจากท่าน (n)" เด่นชัด

### 5.3 หน้าหลักผู้เสนอ / หัวหน้างาน (P1, mobile-first)

- "สิ่งที่ต้องทำ": ร่างที่ค้าง, รอขออนุญาต (ถึงไตรมาสที่วางแผนแล้ว), รายงานผลค้าง พร้อมจำนวนวันที่เกิน
- การ์ดโครงการของฉัน/หน่วยงาน: ชื่อ · สถานะ · สัญญาณไฟ · แถบ อนุมัติ / ใช้ไปแล้ว
- ปุ่มลอย "เสนอโครงการใหม่" (เปิดเฉพาะช่วงรับข้อเสนอ)

### 5.4 รายการโครงการ (P1)

ตารางคอลัมน์: รหัส · ชื่อ · หน่วยงาน · แหล่งเงิน (จุดสี) · ขอ · อนุมัติ · จ่ายจริง · ไตรมาสที่วางแผน · สถานะ · สัญญาณไฟ
ตัวกรองด้านบน + ค้นหา + บันทึกมุมมอง (saved views) + ส่งออก Excel; มือถือแสดงเป็นการ์ด

### 5.5 ฟอร์มเสนอโครงการ — Wizard 6 ขั้น (P1, ต้องใช้บนมือถือได้)

แถบความคืบหน้าด้านบน, บันทึกร่างอัตโนมัติ, กลับไปแก้ขั้นก่อนได้

1. **ข้อมูลทั่วไป** — ชื่อ, หน่วยงาน, ผู้รับผิดชอบ (หลายคน), ลักษณะโครงการ, ใหม่/ต่อเนื่อง (ถ้าต่อเนื่อง เลือกโครงการปีก่อนและแสดงผลปีก่อนย่อ ๆ)
2. **ความสอดคล้อง** — กลุ่ม checkbox แยกหัวข้อ: ยุทธศาสตร์ชาติ, นโยบาย/ยุทธศาสตร์ สอศ., พันธกิจ/กลยุทธ์สถานศึกษา, มาตรฐานการอาชีวศึกษา + ตัวชี้วัด, ปรัชญาเศรษฐกิจพอเพียง (ยุบ/ขยายได้, แสดงจำนวนที่เลือก)
3. **หลักการและเป้าหมาย** — หลักการและเหตุผล, วัตถุประสงค์ (เพิ่มเป็นข้อ), เป้าหมายเชิงปริมาณ/คุณภาพ, ตัวชี้วัด (ชื่อ · ค่าเป้าหมาย · หน่วย), กลุ่มเป้าหมาย/จำนวน, สถานที่
4. **เหตุจำเป็นและผลกระทบ** — ระดับความจำเป็น 3 ระดับเป็นการ์ดเลือก (จำเป็นต้องทำ / ควรทำ / ทำได้ถ้ามีงบ), เหตุจำเป็น, ผลกระทบหากไม่ได้รับอนุมัติ (บังคับเมื่อเลือก "จำเป็นต้องทำ"), ด้านที่กระทบ + ระดับ (ผู้เรียน / ความปลอดภัย / การประเมินคุณภาพ / ข้อผูกพันภายนอก), จำนวนผู้เรียนที่ได้ประโยชน์
5. **งบประมาณ** — ตารางรายการแก้ไขในตัว (หมวด · รายการ · จำนวน · หน่วย · ราคา/หน่วย · รวม · แหล่งเงิน) สรุปยอดแยกหมวดและแหล่งเงินแบบสด; แผนใช้เงินรายเดือน ต.ค.–ก.ย. (ช่องกรอก 12 ช่อง + ปุ่ม "กระจายตามไตรมาส"); **วงเงินขั้นต่ำที่ยังทำได้**; สวิตช์ **แบ่งเป็นระยะ** → ตารางระยะ + วงเงิน
   - บนมือถือ ตารางรายการเปลี่ยนเป็นการ์ดรายการ + ปุ่มเพิ่ม
   - แถบเตือนสดเมื่อ: ยอดรายการ ≠ ยอดแผนรายเดือน, วงเงินขั้นต่ำ > ยอดขอ, หมวดไม่ตรงเงื่อนไขแหล่งเงิน
6. **กิจกรรมและไฟล์แนบ** — ตารางขั้นตอน PDCA × เดือน (กดเลือกช่องเดือนแบบ Gantt ง่าย ๆ), ผลที่คาดว่าจะได้รับ, อัปโหลดไฟล์แบบลากวาง ระบุประเภทไฟล์
   - หน้าสรุปก่อนส่ง: ตรวจครบถ้วน (เช็กลิสต์สีเขียว/แดง) + ปุ่ม "เสนอโครงการ" + "พิมพ์แบบเสนอ (PDF)"

### 5.6 รายละเอียดโครงการ (P1)

หัวหน้า: ชื่อ, รหัส, หน่วยงาน, ป้ายสถานะ, สัญญาณไฟ, ปุ่มการกระทำตามสิทธิ์ (เห็นชอบ / ส่งกลับ / ขออนุญาต / รายงานผล / ขอปรับแผน)
**แถบเงิน 4 ระดับ** ต่อแหล่งเงิน: อนุมัติ → อนุญาตแล้ว → ผูกพัน → จ่ายจริง (แสดงเป็นแถบซ้อนและตัวเลข)

แท็บ:
- **ภาพรวม** — ข้อมูลจากฟอร์มแบบอ่าน
- **งบประมาณ** — รายการค่าใช้จ่าย, แผนรายเดือนเทียบจ่ายจริง
- **การอนุมัติ** — timeline แนวตั้งทุกขั้น (ใคร · ผล · ความเห็น · เวลา) ทั้งชั้นที่ 1 และทุกรอบขออนุญาต
- **ติดตาม** — ความก้าวหน้า (%) + บันทึก + รูป, ผูกพัน/เบิกจ่าย, ตัวชี้วัดเป้าหมายเทียบผลจริง
- **เอกสาร** — ไฟล์แนบทั้งหมดตามประเภท
- **ที่มาของเงิน** — แผนภาพต้นไม้/ไหล (กองเงิน → โครงการ, และโครงการต้นทางจากการปรับแผน พร้อมเลขคำขอ)
- **ประวัติ** — audit log

### 5.7 กล่องงานอนุมัติ + หน้าพิจารณา (P1, mobile-first)

- รายการงานรอ: ประเภท (เสนอ / ขออนุญาต / ปรับแผน / ใช้งบเพิ่ม), ชื่อโครงการ, ยอดเงิน, ผู้ขอ, รอมาแล้วกี่วัน
- หน้าพิจารณา: สรุปสาระสั้น (ไม่เกินหนึ่งจอมือถือ) → ยอดเงินและกองเงินที่ได้รับผลกระทบ (คงเหลือก่อน/หลัง) → ลิงก์ดูรายละเอียดเต็ม → ช่องความเห็น → ปุ่ม เห็นชอบ / ส่งกลับแก้ไข / ไม่เห็นชอบ (สองปุ่มหลังบังคับเหตุผล)
- คำขอ "ใช้งบเพิ่ม" ต้องมีป้ายเตือนสีส้มเด่นและแสดงข้อสังเกตของผู้ขอก่อนปุ่ม

### 5.8 เครื่องมือจำลองงบ — Scenario Workspace (P1, desktop, หน้าที่สำคัญที่สุด)

เลย์เอาต์ 3 ส่วน:

- **แถบบน (ตรึง)**: ชื่อชุดพิจารณา · สลับชุด · แถบสถานะเงินทุกกอง (วงเงินจัดสรรได้ / จัดสรรในชุดนี้ / คงเหลือ — เปลี่ยนเป็นแดงทันทีเมื่อติดลบ)
- **ซ้าย (หลัก)**: ตารางโครงการทั้งหมดในรอบ เรียงตามคะแนน คอลัมน์: คะแนน · ชื่อ · หน่วยงาน · ความจำเป็น · ยอดขอ · วงเงินขั้นต่ำ · ผลพิจารณา (dropdown 5 แบบ: อนุมัติเต็ม / บางส่วน / ระยะที่ 1 / รอเงินเพิ่ม / ไม่อนุมัติ) · วงเงินที่ให้ (แก้ได้เมื่อ "บางส่วน") · ไอคอนล็อก
  - คลิกแถว → แผงด้านข้างแสดงเหตุจำเป็น ผลกระทบ งบรายการ ผลปีก่อน
  - เลือกหลายแถวแล้วเปลี่ยนผลพร้อมกันได้
- **ขวา (แผงเครื่องมือ)**:
  - น้ำหนักคะแนน 5 ตัว (slider + ตัวเลข, รวมต้องเป็น 100) — เปลี่ยนแล้วตารางเรียงใหม่สด
  - ปุ่ม **เติมอัตโนมัติตามคะแนน**, **ลดเท่ากันทุกโครงการ x%**, **ทดสอบรายรับลดลง** (slider 0–20%: แถวที่จะหลุดเปลี่ยนเป็นสีจาง + ขีด)
  - กราฟการกระจายเงิน: ตามฝ่าย/แผนกวิชา เทียบสัดส่วนผู้เรียน, ตามยุทธศาสตร์/มาตรฐาน
- ปุ่มท้าย: "ทำสำเนาชุดนี้" · "เทียบชุด" · "ส่งออกเอกสารเสนอที่ประชุม"

สถานะเปลี่ยนแปลงต้องลื่น (ไม่โหลดหน้าใหม่) และมี undo/redo

### 5.9 เทียบชุดพิจารณา (P2)

2–3 คอลัมน์เคียงกัน: ยอดรวมรายกอง, จำนวนโครงการผ่าน, แล้วรายการเฉพาะโครงการที่ผลต่างกัน (ไฮไลต์)

### 5.10 บันทึกมติ / ยืนยันแผนตั้งต้น (P1)

ฟอร์ม: ครั้งที่/วันที่ประชุม · ชุดพิจารณาที่ใช้ · แก้ผลตามมติ (ตารางเดียวกับ 5.8 แบบย่อ) · แนบรายงานการประชุม → ปุ่ม **"ยืนยันเป็นแผนตั้งต้น"** ต้องมี dialog ยืนยันที่สรุปยอดรายกองและจำนวนโครงการ และแจ้งว่ายกเลิกไม่ได้ (แก้ภายหลังผ่านการปรับแผนเท่านั้น)

### 5.11 ขออนุญาตดำเนินโครงการ (P1, mobile)

ฟอร์มสั้น: วันที่ดำเนินการ · สถานที่ · วงเงินที่ขอใช้รอบนี้ (แยกตามแหล่งเงิน, แสดงยอดอนุมัติคงเหลือข้าง ๆ) · รายการวัสดุที่จะซื้อ (ตาราง) · หมายเหตุ
ระบบแสดงผลตรวจเงินตามกฎกองเงินทันที (ผ่าน ✓ / ไม่ผ่าน พร้อมเหตุผล เช่น "เงินรายได้ที่รับจริงคงเหลือไม่พอ ขาด 12,500 บาท")

### 5.12 บันทึกผูกพัน / เบิกจ่าย (P1, desktop, การเงิน-พัสดุ)

ค้นหาโครงการ → เลือกแหล่งเงินและหมวด → จำนวน · วันที่ · เลขที่เอกสาร · แนบหลักฐาน แสดงยอดคงเหลือของโครงการก่อน/หลังบันทึก รองรับบันทึกหลายรายการต่อเนื่องด้วยแป้นพิมพ์

### 5.13 รายงานผลโครงการ (P1, mobile)

ตัวชี้วัด: เป้าหมาย vs ผลจริง (กรอกผลจริง) · ผลผลิต/ผลลัพธ์ · ตารางงบตามแผน vs ใช้จริง (ดึงยอดจ่ายจริงมาให้อัตโนมัติ) · ปัญหาอุปสรรค · ข้อเสนอแนะ · รูป/หลักฐาน → ส่ง → งานแผนฯ ตรวจ → ปิดโครงการ (แสดง "เงินเหลือจ่ายที่จะคืนกอง")

### 5.14 คำขอปรับแผน (P1, desktop + ดูบนมือถือได้)

ตัวสร้างคำขอแบบ **ต้นทาง → ปลายทาง**:
- เลือกประเภท: แก้รายละเอียด / เปลี่ยนรายการ-หมวด / แยก / รวม / เปลี่ยนโครงการ / ขอเพิ่มวงเงิน
- คอลัมน์ซ้าย **ต้นทาง**: เลือกโครงการ (ได้หลายโครงการ) แต่ละโครงการแสดง "ยอดที่โอนได้" ต่อแหล่งเงิน แล้วกรอกจำนวนที่ให้
- คอลัมน์ขวา **ปลายทาง**: โครงการเดิมหรือสร้างโครงการใหม่ (เปิดฟอร์มย่อ ดึงข้อมูลจากต้นทางมาเป็นค่าเริ่มต้น) กรอกจำนวนต่อแหล่งเงิน
- กลาง/ล่าง: **ตาราง Δ รายกองเงิน** (ให้ − รับ) — Δ ≤ 0 แสดงเขียว "ผ่านตามปกติ · เงินเหลือจ่าย x บาทคืนกอง"; Δ > 0 แสดงแถบส้ม **"ใช้งบเพิ่ม"** และเปิดช่องบังคับ: จำนวนที่เพิ่ม · กองเงินที่ใช้ (แสดงวงเงินคงเหลือของกองนั้น) · เหตุผลและข้อสังเกต
- แผนภาพเล็กแสดงการไหลของเงินจากต้นทางไปปลายทาง (แบบ Sankey ง่าย ๆ)

### 5.15 ภาพรวมกองเงิน + สมุดบัญชี (P1, desktop)

- ภาพรวม: การ์ดต่อกองเงิน (ผังต้นไม้ขยายได้: กองหลัก → กองย่อย) แต่ละการ์ด: ยกมา · ประมาณการ · รับจริง · ส่วนต่าง · กันไว้ · จัดสรร · ผูกพัน · จ่าย · **คงเหลือจัดสรรได้ (จริง)** และ **(ตามประมาณการ)**
- กราฟรายงวด: ประมาณการรับ vs รับจริงสะสม
- สมุดบัญชี: ตารางรายการเคลื่อนไหว (วันที่ · ประเภท · จาก → ไป · แหล่งเงิน · หมวด · จำนวน · เอกสารอ้างอิง · ผู้บันทึก) กรองได้ทุกคอลัมน์; รายการที่ถูกกลับแสดงขีดฆ่า + ลิงก์ไปรายการกลับ

### 5.16 ประมาณการรายรับ / บันทึกรับเงิน (P1)

- ประมาณการ: ตารางรายการต่อกองเงิน มีฐานคำนวณ (เช่น จำนวนผู้เรียน × อัตรา × ภาคเรียน) และเวอร์ชัน (ฉบับต้นปี / ปรับกลางปี)
- รับเงิน: ฟอร์ม กองเงิน · งวด · วันที่เงินเข้า · จำนวน · เลขที่หนังสือ/ใบเสร็จ · แนบไฟล์ → หลังบันทึกแสดงผลกระทบ "รับจริงสะสม vs ประมาณการ"

### 5.17 ศูนย์รายงาน (P2)

การ์ดรายงาน: เล่มแผนปฏิบัติราชการ (ส่วนที่ 3) · รายงานรอบ 6/9/12 เดือน · เทียบแผนตั้งต้น-ปัจจุบัน · ฐานะเงินรายกอง · ตามยุทธศาสตร์/มาตรฐาน · แบบฟอร์มรายโครงการ แต่ละการ์ดเลือกตัวกรองแล้วกด PDF / Excel

### 5.18 ตั้งค่า (P2)

ปีงบประมาณและช่วงเวลา (เปิดรับข้อเสนอ ฯลฯ) · หน่วยงาน (ต้นไม้) · ผู้ใช้และบทบาท · แหล่งเงิน (ต้นไม้ + กฎตรวจเงิน + หมวดที่อนุญาต) · หมวดรายจ่าย · รายการความสอดคล้อง · สายอนุมัติ (ตัวแก้ขั้นตอนแบบลากเรียง) · น้ำหนักคะแนนเริ่มต้น · เกณฑ์สัญญาณไฟ · การแจ้งเตือน

## 7. ทิศทางภาพ (Visual direction)

- อารมณ์: หน่วยงานราชการที่ทันสมัย — สงบ น่าเชื่อถือ อ่านตัวเลขง่าย ไม่ฉูดฉาด
- ฟอนต์ UI: **IBM Plex Sans Thai** หรือ **Sarabun** (Google Fonts) · ตัวเลขแบบ tabular · เอกสารพิมพ์ (PDF) ใช้ TH Sarabun New
- พื้นหลังสว่างเป็นหลัก รองรับโหมดมืด
- **สีประจำกองเงิน** (หลีกเลี่ยงแดง/เขียวเพราะใช้กับสัญญาณไฟ):
  - เงินงบประมาณ — น้ำเงิน
  - เงินอุดหนุน — เขียวอมฟ้า (teal)
  - เงินรายได้สถานศึกษา — อำพัน (amber)
  - เงินบริจาค/อื่น ๆ — ม่วง
- สีเชิงความหมาย: เขียว = ผ่าน/ตามแผน, เหลือง = ล่าช้า, ส้ม = ใช้งบเพิ่ม/ต้องระวัง, แดง = ติดลบ/เสี่ยง
- ตารางหนาแน่นสำหรับงานแผนฯ (แถวสูง ~36 px) และโหมดสบายตาสำหรับผู้ใช้ทั่วไป
- ไอคอน: ชุดเดียวทั้งระบบ เส้นบาง (เช่น Lucide)

## 9. สิ่งที่ขอจาก Claude Design

1. Design system ย่อ: สี (รวมสีกองเงิน/สถานะ), ตัวอักษร, ระยะ, ตาราง, ป้าย, การ์ดเงิน, แถบเงิน 4 ระดับ, ฟอร์ม, dialog ยืนยัน
2. หน้าจอ P1 ทั้งหมดในข้อ 5 (desktop สำหรับหน้าที่งานแผนฯ ใช้, mobile สำหรับหน้าที่ครู/ผู้บริหารใช้)
3. ให้ความสำคัญเป็นพิเศษกับ 3 หน้า: **5.8 เครื่องมือจำลองงบ**, **5.14 คำขอปรับแผน**, **5.5 ฟอร์มเสนอโครงการบนมือถือ**
4. แสดงสถานะว่าง (empty), กำลังโหลด, ข้อผิดพลาด และสถานะเตือน (ติดลบ / ใช้งบเพิ่ม) ของหน้าหลัก
