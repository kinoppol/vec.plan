# ระบบแผนงานและงบประมาณ สถานศึกษาอาชีวศึกษา

เว็บแอปสำหรับงานยุทธศาสตร์ แผนงานและงบประมาณของวิทยาลัย (สังกัด สอศ.) สร้างตาม
[`docs/build-spec.md`](docs/build-spec.md) และดีไซน์ใน [`project/`](project/) (Claude Design handoff)

**สถานะ: ระยะที่ 1** (spec §14) — ฐานระบบ, บทบาท, ข้อมูลหลัก, สมุดบัญชีเงินแบบ append-only,
ประมาณการรายรับ, รับเงิน, ยกมา/ปรับจัดสรร/กันเงิน, นำเข้าแผนที่อนุมัติจาก Excel, ภาพรวมกองเงิน + สมุดบัญชี
พร้อมตัวติดตั้ง `install.php` และเมนู Migrations สำหรับผู้ดูแลระบบ
เมนูของระยะที่ 2–4 แสดงเป็นสีจางพร้อมป้าย "ระยะที่ n"

## เทคโนโลยี

| ชั้น | เทคโนโลยี |
|---|---|
| Backend | PHP 8.0+ (ไม่ใช้ framework / composer) + PDO |
| ฐานข้อมูล | MariaDB 10.2.7+ (หรือ MySQL 8.0.16+) — `DECIMAL(14,2)`, CHECK constraints, trigger กัน UPDATE/DELETE บนสมุดบัญชี |
| Frontend | React 18 UMD + Babel standalone (แปลง JSX ในเบราว์เซอร์ ไม่มีขั้นตอน build) |
| ไฟล์ Excel | อ่าน/เขียน .xlsx เองด้วย zlib (ไม่ต้องใช้ ext-zip) |

> สเปกเสนอ Laravel/PostgreSQL/Vue — ผู้ใช้เลือก PHP ล้วน + MariaDB + React UMD (ตัดสินใจ 6 ต.ค. 2569)

## ติดตั้ง

1. วางโฟลเดอร์ไว้ใต้ web root (เช่น `C:\xampp\htdocs\vec.plan`)
2. เปิด `http://localhost/vec.plan/install.php`
   1. **ตรวจสอบระบบ** — เวอร์ชัน PHP, ส่วนขยายที่ต้องการ, ทดสอบสิทธิ์อ่าน/เขียนจริงใน `config/`, `storage/`, `uploads/`, `migrations/`
   2. **ฐานข้อมูล** — ทดสอบการเชื่อมต่อ, สร้างฐานข้อมูลให้ได้, ตรวจเวอร์ชันและสิทธิ์ CREATE/TRIGGER/CHECK
   3. **ตัวเลือก** — เลือก **สถานศึกษาเดียว** หรือ **หลายสถานศึกษา** · ติดตั้งใหม่ทั้งหมด (ต้องพิมพ์ชื่อฐานข้อมูลยืนยันถ้ามีตารางเดิม) หรือ คงข้อมูลเดิม (อัปเกรด: รันเฉพาะ migration ที่ค้าง) · เลือกใส่ข้อมูลตัวอย่างได้
   4. **ผู้ดูแลระบบ** — ตั้งชื่อผู้ใช้/รหัสผ่าน (≥ 8 ตัว) หรือรีเซ็ตรหัสผ่านของผู้ดูแลเดิม (โหมดหลายสถานศึกษา = ผู้ดูแลระบบกลาง)
3. เข้าระบบที่ `http://localhost/vec.plan/` แล้วไปที่ **ผู้ใช้และบทบาท** เพื่อเพิ่มเจ้าหน้าที่งานแผนฯ / การเงิน
   (โหมดหลายสถานศึกษา: ไปที่ **สถานศึกษา** เพื่อกำหนดผู้ดูแลระบบของแต่ละสถานศึกษาก่อน)

## สถานศึกษาเดียว / หลายสถานศึกษา

| | สถานศึกษาเดียว | หลายสถานศึกษา |
|---|---|---|
| ผู้ดูแลระบบสถานศึกษา (`admin`) | ดูแลทั้งระบบ: ผู้ใช้ บทบาท migrations สำรองข้อมูล audit log | จัดการผู้ใช้/บทบาท และดู audit log ได้เฉพาะสถานศึกษาของตัวเอง |
| ผู้ดูแลระบบกลาง (`super_admin`) | — | ไม่สังกัดสถานศึกษา · สร้าง/ปิดสถานศึกษา กำหนดผู้ดูแลระบบสถานศึกษา รัน migrations สำรองข้อมูล ดู audit log ทุกแห่ง · ไม่เห็นข้อมูลงบประมาณ |

- ข้อมูลแยกตามสถานศึกษา: ปีงบประมาณ (และทุกอย่างที่ผูกกับปี: แหล่งเงิน ประมาณการ โครงการ สมุดบัญชี ความสอดคล้อง สายอนุมัติ), หน่วยงาน, หมวดรายจ่าย, ผู้ใช้, ค่าตั้งค่า, audit log, เลขที่เอกสาร (เช่น `LG70-00001` เริ่มใหม่ในแต่ละแห่ง)
- ทุก API ตรวจว่าปีงบประมาณ/หน่วยงาน/ผู้ใช้ที่อ้างถึงเป็นของสถานศึกษาของผู้ใช้ — ของสถานศึกษาอื่นตอบ 404
- ชื่อผู้ใช้และอีเมลไม่ซ้ำกันทั้งระบบ (หน้าเข้าสู่ระบบไม่ต้องเลือกสถานศึกษา)
- ปิดใช้งานสถานศึกษาแล้ว ผู้ใช้ของแห่งนั้นเข้าระบบไม่ได้ และถูกออกจากระบบในคำขอถัดไป
- **เปิดใช้งานแบบหลายสถานศึกษาภายหลัง:** ผู้ดูแลระบบของระบบที่ใช้แบบสถานศึกษาเดียว ไปที่ **ผู้ดูแลระบบ › สถานศึกษา** แล้วกด
  "เปิดใช้งานแบบหลายสถานศึกษา" (ยืนยันด้วยรหัสผ่าน) — ข้อมูลเดิมเป็นของสถานศึกษาแรก บัญชีนั้นกลายเป็นผู้ดูแลระบบกลาง
  (บทบาทเดิมถูกถอด) จากนั้นกำหนดผู้ดูแลระบบให้สถานศึกษาแรกจากหน้าเดียวกัน · ย้อนกลับเป็นสถานศึกษาเดียวจากหน้าจอไม่ได้

**ติดตั้งซ้ำ:** เรียก `install.php` ได้ทุกเมื่อ แต่เมื่อระบบติดตั้งแล้วต้องยืนยันตัวตนด้วยบัญชีผู้ดูแลระบบ
(หรือรหัสผ่านฐานข้อมูลถ้ามีตั้งไว้) ก่อน · ถ้าฐานข้อมูลเสียและไม่มีรหัสผ่านฐานข้อมูล ให้ลบ `storage/installed.lock` บนเซิร์ฟเวอร์

**ข้อมูลตัวอย่าง** (เลือกตอนติดตั้ง): ผู้ใช้ `planner`, `finance`, `procurement`, `director`, `plandeputy`, `acddeputy`,
`autohead`, `teacher`, `board` รหัสผ่าน `demo-password` — ปิดบัญชีเหล่านี้ก่อนใช้งานจริง

## Migrations

ไฟล์อยู่ใน [`migrations/`](migrations/) ชื่อ `YYYY_MM_DD_HHMMSS_name.sql` แบ่งส่วนด้วย `-- @description`, `-- @up`, `-- @down`
(หรือ `.php` ที่ return `['up' => fn(PDO $pdo) => ..., 'down' => ...]` สำหรับ data migration)

เมนู **ผู้ดูแลระบบ › Migrations ฐานข้อมูล**: ดูสถานะ/batch/ผู้รัน, ดู SQL, รันที่ค้างทั้งหมดหรือทีละไฟล์,
ย้อน batch ล่าสุดหรือทีละไฟล์, ทำเครื่องหมายว่ารันแล้ว/ยังไม่รัน, สร้างไฟล์ใหม่จากหน้าเว็บ,
สำรองฐานข้อมูลอัตโนมัติก่อนรัน/ย้อน และเตือนเมื่อไฟล์ถูกแก้ไขหลังรัน (checksum)
MariaDB commit DDL ทันที ระบบจึงบันทึกทีละไฟล์และหยุดที่ไฟล์แรกที่ล้มเหลว

เมื่อเพิ่ม migration ในโค้ด ให้ commit ไฟล์เข้า git แล้วรันจากเมนูนี้ (หรือ install.php โหมดอัปเกรด) บนทุกเครื่อง

## สำรองข้อมูล

เมนู **ผู้ดูแลระบบ › สำรองข้อมูล** › "สำรองข้อมูลตอนนี้" เลือกได้ 2 แบบ (ไฟล์ `.sql.gz` ใน `storage/backups/`):

- **ทั้งระบบ** — ทุกตารางทุกแถว มี `DROP TABLE` จึงกู้คืนทับฐานข้อมูลเดิมได้
- **เลือกปีงบประมาณ** (หนึ่งปีขึ้นไปของสถานศึกษาเดียว) — โครงสร้างทุกตาราง + เฉพาะข้อมูลของปีที่เลือก
  (แหล่งเงิน ประมาณการ โครงการ รายการงบ สมุดบัญชี ไฟล์แนบ(ข้อมูล) ความสอดคล้อง สายอนุมัติ บทบาทของปีนั้น audit log ในช่วงปี)
  พร้อมข้อมูลหลักที่อ้างถึง (สถานศึกษา หน่วยงาน หมวดรายจ่าย ผู้ใช้ ตั้งค่า ตัวนับเลขที่) · ไม่มี `DROP TABLE`
  จึง **กู้คืนได้ในฐานข้อมูลว่างเท่านั้น** — ถ้าเผลอกู้คืนทับฐานข้อมูลที่ใช้งานอยู่ จะหยุดที่ `CREATE TABLE` แรกโดยไม่ลบข้อมูลปีอื่น
  · ชื่อไฟล์เช่น `backup_20261007_090000_fy2570_MAIN.sql.gz` · ไฟล์ใน `uploads/` ต้องสำรองแยก

## โอนข้อมูลผู้ใช้จากระบบ RMS

เมนู **ตั้งค่า › ข้อมูลผู้ใช้จาก RMS** (ผู้ดูแลระบบสถานศึกษา) หรือปุ่ม "โอนข้อมูลจาก RMS" ในหน้าผู้ใช้และบทบาท

- **URL ของ RMS** (เช่น `http://rms.rvc.ac.th`) เก็บในฐานข้อมูล `settings.rms_base_url` **แยกตามสถานศึกษา** ผู้ดูแลเปลี่ยนได้เอง ·
  ส่วนพาธ `/api_connection.php?app_name=nutty&data=people` และ `/files/` อยู่ในโค้ด (`app/RmsSync.php`)
- โอนเฉพาะ `people_exit = 0` · `people_id` → ชื่อผู้ใช้ · `people_name` + เว้นวรรค + `people_surname` → ชื่อ · `people_email` → อีเมล
  (รูปแบบผิดหรือซ้ำกับผู้ใช้อื่น = ไม่บันทึกอีเมล) · `ath_pass` → รหัสผ่าน (password_hash ก่อนเก็บ)
- `people_pic` → ดาวน์โหลด `{URL}/files/{people_pic}` เก็บใน `uploads/avatars/` เป็นรูปโปรไฟล์ — รูปเกิน 512 px หรือ 200 KB ถูกย่อเป็น JPEG ≤ 512 px (หมุนตาม EXIF, ใช้ extension gd) · ไฟล์ที่ไม่ใช่รูป (เช่น PDF) ถูกข้าม ·
  ผู้ที่ไม่มีรูปแสดงอักษรย่อตามเดิม · โอนซ้ำจะดาวน์โหลดใหม่เฉพาะเมื่อชื่อไฟล์รูปเปลี่ยน
- โอนซ้ำได้: จับคู่ด้วยชื่อผู้ใช้ ปรับชื่อ/อีเมล/รหัสผ่าน/รูป โดย **ไม่เปลี่ยน created_at** บทบาท และสถานะใช้งาน ·
  ไม่ยึดชื่อผู้ใช้ที่เป็นของสถานศึกษาอื่น · ปุ่ม "ตรวจสอบข้อมูล" แสดงผลก่อนโดยไม่บันทึก
- ถ้า RMS ไม่ส่ง `ath_pass` ผู้ใช้ใหม่จะได้รหัสผ่านสุ่มที่ไม่มีใครรู้ (เข้าระบบไม่ได้จนกว่าผู้ดูแลรีเซ็ตรหัสผ่าน)

## ผู้ช่วย AI

ปุ่มลอยมุมขวาล่าง (ไอคอนประกาย) เปิดช่องสนทนากับผู้ช่วย AI — ถามข้อมูลภาพรวม กองเงิน โครงการ สมุดบัญชี ประมาณการรายรับ
หรือสั่งให้ช่วยบันทึก/พาไปหน้าที่ต้องการ

- **ตั้งค่า**: เมนู **ผู้ดูแลระบบ › ผู้ช่วย AI** (ผู้ดูแลระบบสถานศึกษา) · โหมดหลายสถานศึกษา **แต่ละสถานศึกษามีการเชื่อมต่อ API ของตนเอง แยกจากกันทั้งหมด**
- **หลายการเชื่อมต่อ**: เพิ่มได้หลายรายการ (ตาราง `ai_connections`) เปิด/ปิดทีละรายการ · กด "ทดสอบการเชื่อมต่อและดึงรายชื่อโมเดล" (อ่าน `{Base URL}/models`)
  แล้วติ๊กเฉพาะโมเดลที่จะเปิดให้ใช้ พร้อมกำหนดโมเดลเริ่มต้น และปุ่ม "ทดสอบ" รายโมเดล (ถามสั้น ๆ พร้อมเครื่องมือ 1 ตัว) · ถ้าเซิร์ฟเวอร์ไม่มี `/models` พิมพ์ชื่อโมเดลเองได้
- **ผู้ใช้เลือกเอง**: เมื่อเปิดมากกว่า 1 โมเดล หน้าต่างสนทนามีตัวเลือก API/โมเดล (จำค่าไว้ในเบราว์เซอร์) · ถ้าตัวที่เลือกถูกปิด จะกลับไปใช้ค่าเริ่มต้น
- **ผู้ให้บริการ**: ทุกตัวที่รองรับ OpenAI Chat Completions API — OpenRouter, Google AI Studio (`…/v1beta/openai`), OpenAI,
  Ollama, LM Studio, vLLM ฯลฯ · ควรใช้โมเดลที่รองรับ tool/function calling
- **API key** เก็บแบบเข้ารหัส AES-256-GCM ด้วย `app.key` ใน `config/config.php` ไม่ส่งกลับไปที่เบราว์เซอร์ และส่งไปเฉพาะ URL ที่บันทึกคู่กัน (เปลี่ยน URL ต้องใส่คีย์ใหม่)
- **สิทธิ์**: ผู้ช่วยเรียก API handler เดิมในนามผู้ใช้ที่สนทนา (`api_call()`) จึงเห็น/ทำได้เท่าบทบาทของผู้ใช้คนนั้น ·
  การบันทึก/แก้ไข (บันทึกรายการกองเงิน กลับรายการ ประมาณการรายรับ) **ต้องกดยืนยันในการ์ดทุกครั้ง** และบันทึก audit `ai.*` ·
  ปิด "อนุญาตให้ผู้ช่วยบันทึก/แก้ไขข้อมูล" ได้ถ้าต้องการให้ดูอย่างเดียว
- **พูดแทนพิมพ์**: ปุ่มไมค์ใช้ Web Speech API ของเบราว์เซอร์ (ภาษาไทย; Chrome/Edge/Safari) ต้องเปิดผ่าน HTTPS หรือ localhost
- ประวัติสนทนาเก็บใน sessionStorage ของเบราว์เซอร์ (ต่อผู้ใช้ต่อปีงบประมาณ) เซิร์ฟเวอร์ไม่เก็บ ·
  ข้อมูลที่ผู้ช่วยค้นได้จะถูกส่งไปผู้ให้บริการ AI — ถ้าต้องการให้อยู่ในองค์กรให้ใช้ Ollama/LM Studio
- XAMPP บน Windows ถ้าเชื่อมต่อ HTTPS ไม่ได้ (SSL certificate problem) ให้ตั้ง `curl.cainfo` ใน `php.ini` ชี้ไปที่ไฟล์ `cacert.pem`
